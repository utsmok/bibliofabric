    Client

    quiddita.QuidditaClient

    Bases: BaseApiClient

    Client for Wikidata: the Action API, the Wikibase REST API, and SPARQL.

    The API needs no credentials, but all three services ask for a descriptive User-Agent with contact information; the client builds it from the settings. www.wikidata.org serves both the Action API (w/api.php) and the Wikibase REST API (w/rest.php/wikibase/v1), so one client covers them. SPARQL lives on query.wikidata.org and is reached through client.sparql.

    Settings

    quiddita.QuidditaSettings

    Bases: BaseApiSettings

    Wikidata-specific client settings.

    Inherits timeout, max_retries, max_retry_wait, max_requests_per_second, max_concurrency, user_agent and mailto from :class:bibliofabric.config.BaseApiSettings. The API needs no credentials, but the MediaWiki Action API, the Wikibase REST API, and the SPARQL query service all ask for a descriptive User-Agent with contact information: effective_user_agent() builds it from user_agent or the package metadata, and mailto is appended when it is set.

    Resource clients

    The entities and search resources inherit the generic operations from bibliofabric.ResourceClient (get, search, iterate, collect, first, count) through quiddita._async.base.WikidataResourceClient. Only the members that Wikidata changes or adds are shown here.

    quiddita._async.entities.EntitiesClient

    Bases: WikidataResourceClient[Entity]

    Client for the wbgetentities module.

    The API answers at most 50 ids per request (toomanyvalues above 50, verified on 2026-11-27). :meth:batch_get chunks through :class:~bibliofabric.ResourceClient; :meth:iterate_ids walks an unbounded id list one chunk at a time, in order.

    iterate_ids(ids, *, props=None, languages=None, sitefilter=None, on_error='raise', failures=None) async

    Iterate over many ids, fetching up to 50 per request, in order.

    Ids are normalized and deduplicated first. An id the API does not know raises NotFoundError; with on_error="skip" it is dropped and recorded in failures instead. props, languages, and sitefilter pass through to wbgetentities.

    _fetch_batch_chunk(field, chunk, *, select=None) async

    Fetch one id chunk.

    An id that the API answers with a missing stub (a deleted item, an unknown lexeme or property) is absent from the result, as the :meth:batch_get contract says. An id that makes the API reject the whole request (no-such-entity) raises NotFoundError.

    quiddita._async.sparql.SparqlClient

    Client for SPARQL SELECT, ASK, and CONSTRUCT queries.

    The query service is a second host, so the :class:QuidditaQueryClient behind this resource is a second API client instance. It shares the settings object and the rate limiter with the main client: SPARQL requests run in the sparql rate class, Action API and REST requests in the default class, and one limiter inside the main client paces both classes. See docs/quiddita/sparql.md.

    The service answers malformed or overlong queries with HTTP 400 and a plain-text Java stack trace; those raise :class:~bibliofabric.exceptions.APIError with the text as the body.

    __init__(query_client)

    Build the resource client on the second-host query client.

    query(query, *, timeout=None) async

    Run a query with GET and return the typed SPARQL 1.1 JSON result.

    query_post(query, *, timeout=None) async

    Run a query with POST and return the typed SPARQL 1.1 JSON result.

    Long queries belong in a POST body: URL length limits do not apply. The POST is read-only, so the request carries retry=True for the framework's transient-failure retries.

    query_text(query, *, format='json', timeout=None) async

    Run a query with GET and return the raw body as text.

    format selects the representation through the Accept header: the service ignores a non-JSON format query parameter and answers SPARQL-result XML unless asked otherwise (verified 2026-11-27). Supported values: json, xml, csv, tsv, turtle. The body passes through as text; only :meth:query and :meth:query_post parse the typed SPARQL 1.1 JSON shape.

    Helpers and dialect

    quiddita.normalize_wikidata_id(value)

    Return the bare canonical Wikidata id (Q42, P31, L1).

    Accepts the id itself (any letter case), the wiki URL form (https://www.wikidata.org/wiki/Q42), and the entity URL form (https://www.wikidata.org/entity/Q42). Raises :class:~bibliofabric.exceptions.ConfigurationError for anything else.

    quiddita.dialect

    Query dialect and endpoint paths for Wikidata.

    All requests go to two hosts. www.wikidata.org serves both the MediaWiki Action API (w/api.php) and the Wikibase REST API (w/rest.php/wikibase/v1), so one client with one rate limiter covers both. The SPARQL query service lives on query.wikidata.org and is served by a second client instance that shares the settings object and the limiter through the sparql rate class.

    Models

    The models live in quiddita.models and are re-exported from the top-level package. They are plain Pydantic models with extra="allow".

    quiddita.models.Entity

    Bases: _WikidataModel

    One entity as returned by wbgetentities.

    Items carry labels, descriptions, aliases, claims, and sitelinks. Properties carry datatype and the term fields. Lexemes and forms carry their own shapes, which extra="allow" keeps.

    label(language='en')

    Return the label in language, or None when there is none.

    description(language='en')

    Return the description in language, or None.

    quiddita.models.Term

    quiddita.models.DataValue

    Bases: _WikidataModel

    The datavalue member of a snak.

    value carries one of the Wikidata value shapes (a string, an entity id object, a time object, a quantity object, a globe-coordinate object, or a monolingual-text object) depending on type. The client keeps it untyped so no payload shape is lost; parse_value and parse_time offer the common shapes as helpers.

    quiddita.models.SparqlBindingValue

    Bases: _SparqlModel

    One typed term of a result row.

    type is one of uri, literal, bnode (SPARQL 1.1 JSON), plus the Wikidata extensions literal-ext and unknown. Literal terms carry xml:lang for language-tagged literals and datatype (an XSD datatype IRI) for typed ones.

    quiddita.models.EntityDataResult

    Bases: _MiscModel

    The typed result of an EntityData read.

    entity is set for format="json"; document is set for the RDF formats. Exactly one of the two carries the payload.

    quiddita.models.EntityDataDocument

    Bases: _MiscModel

    A non-JSON Special:EntityData document (an RDF serialization).

    The RDF formats (jsonld, rdf, nt, ttl, n3) pass through as text; format is the requested suffix and content_type is the Content-Type the service answered with.
