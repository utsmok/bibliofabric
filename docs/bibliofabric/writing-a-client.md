# Building a client on `bibliofabric`

This guide walks through creating a new scholarly API client package on
`bibliofabric` 0.7 — from workspace layout and settings to authentication,
paging, unwrapping, resource hooks, sync-twin generation, testing, and release
registration.

For the rules governing generated synchronous twins (`_sync/`), see
[Writing a client with sync support](authoring-sync.md); this page focuses on
the full client architecture and `bibliofabric` 0.7 API surface.

## 1. Package Layout

Keep pure code (settings, dialect, unwrapper, models, identifier helpers) at
the package root and put every I/O module under `_async/`. Never hand-edit
`_sync/`; `scripts/unasync.py` generates it from `_async/`.

```text
packages/<pkg>/
  pyproject.toml
  CHANGELOG.md
  README.md
  src/<pkg>/
    py.typed
    __init__.py          # re-exports async + generated sync names
    config.py            # BaseApiSettings subclass + get_settings()
    dialect.py           # QueryDialect instance(s)
    unwrap.py            # ResponseUnwrapper implementation
    models/              # Pydantic models (pure)
    _async/
      __init__.py
      client.py          # BaseApiClient subclass
      resources.py       # ResourceClient[E] subclasses (or resources/*.py)
    _sync/               # GENERATED by scripts/unasync.py
  tests/
    _async/              # pytest-httpx tests (source of truth)
    _sync/               # GENERATED by scripts/unasync.py
```

See [Writing a client with sync support](authoring-sync.md) for `_concurrency`
primitives (`sleep`, `Lock`, `Limiter`, `run_bounded`, `maybe_await`), naming
conventions (`FooClient` → `FooSyncClient`, `WorksResource` →
`SyncWorksResource`), and `[tool.unasync]` overrides.

## 2. Configuration (`BaseApiSettings`)

Subclass `BaseApiSettings` with a unique `env_prefix` so environment variables
never collide across sibling libraries, and expose an `lru_cache`-backed
`get_settings()`:

```python
from functools import lru_cache

from pydantic import Field
from pydantic_settings import SettingsConfigDict

from bibliofabric import BaseApiSettings


class ExampleSettings(BaseApiSettings):
    model_config = SettingsConfigDict(
        env_prefix="EXAMPLE_", env_file=".env", extra="ignore"
    )

    api_key: str | None = None
    timeout: float = Field(default=30.0, gt=0)
    connect_timeout: float | None = Field(default=10.0, gt=0)
    follow_redirects: bool = False
    max_requests_per_second: float | None = Field(default=5.0, gt=0)
    rate_limits: dict[str, float | None] = Field(
        default_factory=lambda: {"search": 2.0, "single": 10.0}
    )


@lru_cache(maxsize=1)
def get_settings() -> ExampleSettings:
    return ExampleSettings()
```

Inherited behaviors worth knowing:

- `follow_redirects` (default `False`) and `connect_timeout` (default `None`,
  falling back to `timeout`) apply automatically when `BaseApiClient` creates
  an owned `httpx` client.
- `httpx.Limits` auto-size from `max_concurrency`
  (`max_connections=max(20, max_concurrency * 2)`,
  `max_keepalive_connections=max(10, max_concurrency)`).
- `rate_limits` pairs with `BaseApiClient.rate_class(request)` for per-endpoint
  pacing under a shared concurrency bound; setting a class to `None` disables
  pacing for that class.
- `effective_user_agent()` builds `<package>/<version> (+<homepage>;
  mailto:<mailto>)` automatically from your package metadata when `user_agent`
  is unset.

## 3. Authentication (`AuthStrategy`)

Pick one of the built-in strategies (each implements both `async_authenticate` /
`async_close` and sync `authenticate` / `close`):

| Strategy | When to use |
|---|---|
| `NoAuth()` | Public APIs (default) |
| `HeaderAuth(name, value)` | Static credential headers (e.g. `x-api-key`, `crossref-api-key`, `Client-Id`) |
| `QueryParameterAuth(key_name, key_value)` | Credential query parameters (e.g. `api_key`, `email`) |
| `StaticTokenAuth(token)` | Pre-issued `Authorization: Bearer <token>` |
| `BasicAuth(username, password)` | HTTP Basic (`Authorization: Basic <b64>`, e.g. DataCite Member writes) |
| `ClientCredentialsAuth(client_id, client_secret, token_url, *, scope=None, token_auth_method="basic", ...)` | OAuth2 client-credentials flow with monotonic expiry cache; pass `token_auth_method="post"` when the token endpoint expects form-body credentials (e.g. ORCID) |
| `RefreshTokenAuth(token_url, refresh_token, *, client_id=None, client_secret=None, scope=None, ...)` | OAuth2 refresh-token flow with automatic refresh-token rotation |

### Automatic 401 Refresh & Secret Redaction

- **401 retry-once:** Any strategy implementing `invalidate_token() -> None`
  (including `ClientCredentialsAuth` and `RefreshTokenAuth`) triggers automatic
  token invalidation and a single retry on HTTP 401 inside both `request()` and
  `stream()`.
- **Custom secret redaction:** If you write a custom `AuthStrategy`, declare
  `redacted_query_params: frozenset[str]` and/or `redacted_headers:
  frozenset[str]` (lowercase header names). `BaseApiClient` scrubs those values
  from debug logs and all `BibliofabricError` strings automatically.

## 4. Query Dialect (`QueryDialect`)

Declare paging, sorting, search, and field-selection rules once in a frozen
`QueryDialect`:

```python
from bibliofabric import QueryDialect

DIALECT = QueryDialect(
    page_size_param="per_page",  # None for unpaged APIs (e.g. OpenCitations)
    max_page_size=200,
    default_page_size=25,
    iterate_page_size=200,  # optional larger page size for iterate()
    count_page_size=0,  # 0 when the API supports zero-row count queries
    page_param="page",  # None if page numbers are unsupported
    page_start=1,  # 0 for zero-based APIs
    offset_param=None,  # e.g. "offset" or "start"; replaces page_param
    max_offset=10_000,  # optional hard cap; raises ConfigurationError if exceeded
    cursor_param="cursor",  # takes precedence over page/offset in iterate()
    cursor_start="*",  # set None if the first request omits the cursor param
    sort_param="sort",
    query_param="q",
    select_param="select",
)
```

Key `bibliofabric` 0.7 dialect details:

- **`page_size_param=None`** omits the page-size parameter altogether (useful for
  unpaged endpoints like OpenCitations or fixed-page-size APIs like ROR v2).
- **`cursor_start=None`** sends the initial cursor request without the cursor
  parameter (needed by token-based APIs such as Semantic Scholar bulk search or
  ClinicalTrials.gov `pageToken`).
- **`max_offset`** guards page and offset paging before sending a request,
  raising `ConfigurationError` instead of triggering an upstream 400/500.
- **`count_page_size`** controls what `count()` requests (default `1`; set to
  `0` for APIs that return totals with zero rows).
- **Per-instance override:** Pass `dialect=...` to `ResourceClient(...)` when
  one endpoint differs from the rest of the API (for example Zenodo's 25 unauth
  vs. 100 auth `max_page_size`, or Semantic Scholar's bulk vs. standard search).

## 5. Response Unwrapper (`ResponseUnwrapper`)

Implement the 5-method `ResponseUnwrapper` protocol to teach `bibliofabric` how
to read your API's JSON envelope:

```python
from typing import Any


class ExampleUnwrapper:
    def results(self, body: Any) -> list[dict[str, Any]]:
        return list(body.get("results", []))

    def item(self, body: Any) -> dict[str, Any]:
        return dict(body)

    def total(self, body: Any) -> int | None:
        meta = body.get("meta")
        return meta.get("count") if isinstance(meta, dict) else None

    def next_cursor(self, body: Any) -> str | None:
        meta = body.get("meta")
        return meta.get("next_cursor") if isinstance(meta, dict) else None

    def meta(self, body: Any) -> dict[str, Any]:
        return {k: v for k, v in body.items() if k != "results"}
```

## 6. API Client (`_async/client.py`)

Subclass `BaseApiClient` to wire `base_url`, `settings`, `unwrapper`, `auth`,
resource attributes, and optional HTTP lifecycle hooks:

```python
import httpx

from bibliofabric import AuthStrategy, BaseApiClient, HeaderAuth, NoAuth

from ..config import ExampleSettings, get_settings
from ..unwrap import ExampleUnwrapper
from .resources import WorksResource


class ExampleClient(BaseApiClient):
    def __init__(
        self,
        *,
        settings: ExampleSettings | None = None,
        auth: AuthStrategy | None = None,
        http_client: httpx.AsyncClient | None = None,
    ) -> None:
        resolved = settings or get_settings()
        effective_auth = auth
        if effective_auth is None:
            effective_auth = (
                HeaderAuth("x-api-key", resolved.api_key)
                if resolved.api_key
                else NoAuth()
            )
        super().__init__(
            base_url="https://api.example.org/v1",
            settings=resolved,
            unwrapper=ExampleUnwrapper(),
            auth=effective_auth,
            http_client=http_client,
        )
        self.last_credits_used: str | None = None
        self.works = WorksResource(self)

    def rate_class(self, request: httpx.Request) -> str:
        return "search" if request.url.path.endswith("/works") else "single"

    def on_response(self, response: httpx.Response) -> None:
        # Invoked after every HTTP response, before status errors raise.
        self.last_credits_used = response.headers.get("X-RateLimit-Credits-Used")

    def is_retryable(self, response: httpx.Response) -> bool:
        # Veto retries for non-transient 429s (e.g. exhausted daily budget).
        if response.status_code == 429:
            try:
                if response.json().get("reason") == "daily_budget":
                    return False
            except ValueError:
                pass
        return super().is_retryable(response)
```

Useful `BaseApiClient` capabilities for custom endpoints:

- **`request(..., retry=True | False | None)`:** Default `retry=None` retries
  only idempotent methods (`GET`, `HEAD`, `OPTIONS`, `PUT`, `DELETE`). Pass
  `retry=True` for read-only `POST` batch/search endpoints, or `retry=False` to
  disable retries for a single call.
- **`stream(method, path, ...)`:** Async context manager (sync context manager
  on `SyncBaseApiClient`) for downloading files or bulk dumps incrementally with
  auth, rate limiting, `on_response()`, single-retry 401 refresh, and typed
  error mapping.
- **`parse_json(response)` / `get_json(path, ...)`:** Decode JSON while mapping
  malformed payloads to `APIError`.

## 7. Resource Clients (`_async/resources.py`)

Subclass `ResourceClient[E]` per endpoint and override only the hooks where your
API deviates from the defaults:

```python
from collections.abc import Sequence
from typing import Any

import httpx

from bibliofabric import ResourceClient, normalize_doi, validate_model

from ..dialect import DIALECT
from ..models import Work


class WorksResource(ResourceClient[Work]):
    path = "works"
    model = Work
    dialect = DIALECT
    batch_size = 500

    def normalize_id(self, value: str) -> str:
        return normalize_doi(value)

    async def _fetch_batch_chunk(
        self,
        field: str,
        chunk: list[str],
        *,
        select: Sequence[str] | None = None,
    ) -> tuple[list[dict[str, Any]], httpx.Response]:
        # Override chunk transport for POST-batch APIs while inheriting
        # chunking, deduplication, concurrency, validation, on_error, and keying.
        params = {"fields": ",".join(select)} if select else None
        response = await self._client.request(
            "POST",
            f"{self.path}/batch",
            params=params,
            json={"ids": chunk},
            retry=True,
        )
        raw = self._client.parse_json(response)
        records = [item for item in raw if isinstance(item, dict)]
        return records, response
```

Key `ResourceClient[E]` details:

- **Hook checklist:** `build_filter_params()`, `format_sort()`,
  `build_batch_params()`, `_fetch_batch_chunk()`, `normalize_id()`,
  `record_keys()`, and `item_path()`.
- **Validation & `on_error`:** On the default `on_error="raise"` path,
  `search()`, `iterate()`, and `batch_get()` bulk-validate each page/chunk using
  a lazily cached `TypeAdapter(list[E])` per subclass, falling back to
  per-record validation only on error so `ValidationError.raw` still carries the
  offending payload. Callers can pass `on_error="skip"` and a `failures=[]` list
  to collect bad records without aborting a harvest.
- **Custom endpoints & `validate_model()`:** When writing custom resource
  methods outside `get()`/`search()`, validate payloads with
  `validate_model(Model, data, request=response.request, response=response)` so
  Pydantic errors consistently raise `bibliofabric.ValidationError`.

## 8. Exports (`__init__.py`)

Re-export both async and generated sync classes from your package root so users
never import from `_async` or `_sync` directly:

```python
from ._async.client import ExampleClient
from ._async.resources import WorksResource
from ._sync.client import ExampleSyncClient
from ._sync.resources import SyncWorksResource
from .config import ExampleSettings, get_settings
```

## 9. Testing & Quality Gates

Write offline unit tests in `packages/<pkg>/tests/_async/` using `pytest-httpx`
(never import `asyncio` in `_async` tests; use `bibliofabric._async._concurrency`
primitives if testing concurrency). Running `scripts/unasync.py` mirrors your
async tests into `tests/_sync/` automatically.

Mark any live-network smoke tests with `@pytest.mark.live_api` (deselected by
default in `pytest`).

Before opening a pull request, run every gate from the monorepo root:

```bash
uv run python scripts/unasync.py --package <pkg>
uv run python scripts/unasync.py --check
uv run ruff check
uv run ruff format --check
uv run ty check packages/*/src packages/*/tests scripts/unasync.py
uv run pytest packages/<pkg>/tests
uv run mkdocs build --strict
```

`ty` must pass with zero diagnostics and zero suppression comments
(`# ty: ignore` / `# type: ignore`).

## 10. Monorepo Registration Checklist

When adding a new client package to `utsmok/bibliofabric`:

1. **Workspace & packaging:** Create `packages/<pkg>/pyproject.toml` depending
   on `bibliofabric` (with `py.typed`, Python `>=3.12`, and optional
   `[tool.unasync]`), then run `uv sync --all-packages --all-groups` so the
   root `uv.lock` includes the new workspace member.
2. **Sync generation:** Run `uv run python scripts/unasync.py --package <pkg>`
   and commit the generated `_sync/` and `tests/_sync/` modules.
3. **Documentation (`mkdocs.yml`):**
   - Add `"packages/<pkg>/src"` to `plugins.mkdocstrings.handlers.python.paths`.
   - Add `packages/<pkg>/src/<pkg>` to `watch:`.
   - Add the package's docs under `docs/<pkg>/` and register it under `nav:`
     plus `docs/index.md`.
4. **CI matrix (`.github/workflows/ci.yml`):** Add `<pkg>` to the
   `test.strategy.matrix.package` list so every PR tests Python 3.12, 3.13, and
   3.14.
5. **Changelog & PyPI publishing:**
   - Maintain Keep a Changelog entries in `packages/<pkg>/CHANGELOG.md`.
   - Configure a PyPI **Trusted Publisher** (OIDC) for `<pkg>` pointing to
     `utsmok/bibliofabric`, workflow `ci.yml`, environment `pypi`.
   - Pushing a tag named `<pkg>-v<version>` validates `pyproject.toml`, builds
     the wheel/sdist, publishes to PyPI via OIDC, and creates a GitHub Release
     from `packages/<pkg>/CHANGELOG.md`.
