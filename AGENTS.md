# AGENTS.md

Guidelines for AI agents and contributors working in the bibliofabric
monorepo.

## Rules

- Use `uv` for everything (`uv run`, `uv sync`); never bare `python` or `pip`.
- Conventional commits (`feat:`, `fix:`, `docs:`, `chore:`, ...), short and
  imperative. No AI attribution in commits.
- Never print or commit secrets; live-test credentials come from `.env`
  files that are git-ignored.
- Every package uses async source modules (`_async/`) as the single source
  of truth with committed sync twins (`_sync/`) generated by
  `scripts/unasync.py`; never hand-edit generated `_sync/` files. Use stdlib
  `logging` only (no loguru).
- Errors raise; there are no raw-dict fallbacks. Validation failures raise
  `bibliofabric.ValidationError` with the payload attached.
- `ty` gate is zero diagnostics and zero ignore comments. Fix findings by
  declaring attributes properly; never suppress.

Each `packages/<name>/AGENTS.md` records package-specific facts (architecture,
upstream quirks, testing patterns). Tooling lives only at the root:

- one virtual workspace root `pyproject.toml` (workspace members, `[tool.uv.sources]`
  `bibliofabric = { workspace = true }`, shared `dev` and `docs` groups, ruff and
  pytest config; `ty` needs no config),
- one root `uv.lock`, one root `.python-version` (3.12),
- one CI workflow (`.github/workflows/ci.yml`), one `.pre-commit-config.yaml`,
- one mkdocs site (`mkdocs.yml`, mkdocstrings paths into every `src` tree).

## Commands

Run everything from the repository root:

```bash
uv sync --all-packages --all-groups               # install all packages plus dev/docs groups
uv run pytest                                     # every test suite (live tests deselected)
uv run pytest packages/aletheca/tests             # one package's suite
uv run pytest -m live_api                         # live API smoke tests (needs credentials in .env)
uv run ruff check                                 # lint all packages and scripts/
uv run ruff format --check                        # formatting gate
uv run ty check packages/*/src packages/*/tests scripts/unasync.py # type gate
uv run python scripts/unasync.py --check          # verify generated _sync/ twins are fresh
uv run python scripts/unasync.py                  # regenerate _sync/ twins after _async/ edits
uv run mkdocs build --strict                      # docs gate
uv build --package <name>                         # build one package (wheel contains py.typed)
```

Client packages depend on `bibliofabric>=0.8,<0.9`; inside the workspace uv
resolves that to the sibling package (`[tool.uv.sources]` at the root).

## Wave 1 packages

The eleven Wave 1 packages wait for their first PyPI release. Each name has
three spellings: the distribution and import name (`rorifer`), the settings
environment prefix (`RORIFER_`), and the class prefix (`Rorifer`). The roster
is in `docs/roadmap/wave-1-libraries.md`, and `docs/roadmap/deferred.md`
lists what each package leaves out.

Tests must pass with and without the credentials of `.env` exported in the
shell. Build settings in a test with every credential field explicit, for
example `OrchisSettings(_env_file=None, access_token=None)`, because
`_env_file=None` does not hide environment variables.

`uv run python scripts/unasync.py --package <name>` regenerates the twins of
one package. Without `--package` it regenerates every package.

## Release flow

1. Bump `version` in `packages/<name>/pyproject.toml` and add a Keep a
   Changelog entry to that package's `CHANGELOG.md`. Commit and push `main`.
2. Tag `<name>-v<version>` (example: `aletheca-v0.4.1`) and push the tag.
   A plain `v<version>` tag still publishes bibliofabric.
3. CI runs lint + the test matrix (Python 3.12, 3.13, 3.14), then a publish
   job that runs `uv build --package <name>` and `uv publish dist/*` via OIDC
   to the `pypi` environment, followed by a `release` job that creates a
   GitHub Release from the package's `CHANGELOG.md` (with `--generate-notes`
   fallback). One site deploys docs on pushes to `main`.
4. Verify the release is on PyPI before advertising it; `uv`'s index cache
   can lag a fresh publish for minutes (`uv cache clean <pkg>` if `uv add`
   claims the new version is unavailable).

Per-package release notes go in that package's changelog only; the root
README table lists versions and needs a row update only when a package is
added or renamed.

## Adding a package

Create `packages/<new-name>/` with the family shape (`src/<new_name>/` with
`_async/client.py`, `_async/resources/`, generated `_sync/` twins, and pure
modules `config.py`, `dialect.py`, `unwrapper.py`, `filters.py`, `models/`;
`tests/_async/` with pytest-httpx + generated `tests/_sync/`; `py.typed`;
README and CHANGELOG; run `uv run python scripts/unasync.py` to generate sync
twins). See `docs/bibliofabric/authoring-sync.md` for the sync twin rules. The
`packages/*` workspace glob picks it up automatically; add a docs section and
the `src` path to the root `mkdocs.yml`, the `tests` path to `testpaths` in
the root `pyproject.toml`, a row to the README table, a matrix entry in
`ci.yml`, and a PyPI trusted publisher entry for the new package name. See
`.agents/skills/bibliofabric-sibling-client/` for the full procedure.
